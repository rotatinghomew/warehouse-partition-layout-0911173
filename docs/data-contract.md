# 表布局与查询含义

occurred代表绝对事件时间，region允许空值，event_id是稳定业务键。旧版utc_day来源于UTC日历，不是活动地区业务日。地区业务时区登记在regions.json，不能从地区名称或机器本地时区推断；空地区没有已知地区业务日，其业务日在清单中登记为NULL，布局变化不改变事件时间、业务日与空地区各自的含义。

## 两种物理布局

- `utc_day`（历史布局）：文件按UTC自然日分组，files.day记录UTC日，清单行不携带地区身份。
- `region_biz`（当前布局）：文件按地区与地区业务日分组，files.region与files.biz_day记录分区身份；空地区进入专用空地区目录且biz_day为NULL。业务日只登记在清单中，不写进Parquet载荷，occurred与utc_day载荷字段保持不变。

物理目录名称不能单独证明文件内容范围，表清单中的规格身份（layout/region/biz_day/source_file/checksum）与统计才有可验证含义。读取侧只按清单身份裁剪，重命名或挪动目录不会改变分区判断。迁移复制出的文件只有成为有效清单版本的一部分才参与读取。

## 版本、生效布局与迁移

- settings中的生效布局只决定新写入的落盘方式和下一次发布；历史versions行不可变，旧读者始终按发布时固定的文件集合与布局身份完成读取。
- 布局切换与新版本快照在同一事务提交。发布失败时生效布局保持原值、不留下半版本，已有可读版本继续可用，不会出现目录已换而查询仍按旧目录猜分区的状态。
- 迁移只复制不重写：源文件保持原位不删不改，复制出的region_biz文件通过source_file记录血缘，migration_state按源文件记录副本清单、行数与行级校验和。迁移按源文件逐个事务提交，中断后重跑自动跳过已完成项，可分批继续。
- 任一发布版本中，同一批逻辑数据只暴露一份：已迁移源文件被其副本取代，未迁移源文件与原生新布局文件照常可见。扫描另按event_id做防御性去重，异常清单下也不会返回重复行。

## 候选裁剪与行级过滤

筛选语义为绝对时间半开区间，regions=None表示不限制地区，regions列表里的None表示包含空地区，空列表表示不返回任何地区。

裁剪只使用清单能证明的信息，信息不足时保守读取而不是提前排除候选：

- utc_day文件：仅按UTC日与查询区间是否相交裁剪，不做地区裁剪（旧文件无地区身份）。
- region_biz文件：按业务日在地区时区的UTC边界判断时间相交，再按region身份做地区裁剪。
- region为NULL或biz_day为NULL的文件：时间维度无法证明不相交，一律保守读取；地区筛选仍可按清单中的NULL身份精确裁剪。
- 未登记业务时区等异常身份同样保守读取。

候选裁剪之后始终执行行级精确过滤（半开时间与地区集合）。返回selected、skipped以及逐文件decisions（含time_reason与region_reason）用于核对实际读取范围；它们解释文件选择，不是提前承诺查询一定返回行。新布局在时间+地区组合查询下应比旧布局读取更少的无关文件，而不是通过关闭裁剪来回避正确性。
